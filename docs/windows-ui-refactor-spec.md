# TCHESS Windows JavaFX 界面重构规格

## 1. 目标

重构 TCHESS Windows 版界面，保留现有 JavaFX、棋盘、引擎、连线、棋谱和开局库业务能力，解决旧界面信息层级、操作状态和设置入口不清晰的问题。

本次范围仅包含 Windows 版：

- 主窗口
- 引擎管理与添加窗口
- 引擎时间设置窗口
- 连线设置窗口
- 开局库设置与本地库管理窗口
- 主题设置窗口
- 局面编辑窗口

Android 版不在本次重构范围内。

### 固定产品决策

- 使用现有 JavaFX 23、FXML、CSS 和 Canvas。
- 保留 Windows 原生标题栏；标题栏下实现新的深色导航区。
- 亮色和暗色主题同步重构。
- 主窗口最低可用尺寸为 1280×720。
- 不引入第三方 UI 框架；图标使用 JavaFX `SVGPath`。
- 不改变引擎、连线、棋谱、棋盘识别、UCI/UCCI 或配置文件语义。

## 2. 技术栈与现状

- JDK 21
- JavaFX 23.0.1
- FXML + JavaFX CSS
- Canvas 棋盘渲染
- Maven 构建
- 当前主界面：[src/main/resources/fxml/app.fxml](../src/main/resources/fxml/app.fxml)
- 当前主控制器：[src/main/java/com/sojourners/chess/controller/Controller.java](../src/main/java/com/sojourners/chess/controller/Controller.java)

当前主 FXML 约 42 KB，主控制器约 65 KB。现有连线模式已包含“自动走棋”和“观战模式”，现有分析卡片和主题切换逻辑可复用；本次主要改造视图结构、状态投影和样式系统。

## 3. 界面结构

### 3.1 主窗口

采用“原生标题栏 + 深色导航 + 双栏工作区”：

- 左侧棋盘为主视觉，继续复用 Canvas、棋盘缩放、翻转和点击逻辑。
- 右侧为引擎分析工作区，包含引擎状态、配置摘要、评分、候选着法和下方工作标签。
- 顶部导航显示“对弈、分析、棋谱、开局库”。
- “文件、局面、设置、帮助”等旧命令迁移到应用菜单和更多菜单，原命令全部保留。
- 新建、打开、保存、翻转等高频操作保留为快捷按钮。
- 原独立棋谱侧栏并入右侧“棋谱”标签，避免压缩棋盘区域。

### 3.2 连线工作流

连线状态必须同时使用文字、图标和颜色表达：

| 状态 | 显示 | 可用操作 |
| --- | --- | --- |
| 未连线 | 中性“连线” | 进入目标选择 |
| 选择目标 | 琥珀色“选择目标棋盘…” | 取消选择 |
| 已连线 | 绿色“已连线” | “停止连线” |
| 错误 | 错误图标和文字 | 重试、查看设置 |

已连线时，顶部持续显示“自动走棋 / 观战模式”分段控件：

- 自动走棋：选中态，允许现有自动走子逻辑。
- 观战模式：选中态，仅分析目标局面，不自动走子。

引擎状态必须与棋盘连线状态分开显示，例如“引擎运行中”不能替代“已连线”。

### 3.3 重要设置摘要

Windows 主界面常驻显示关键配置摘要，完整编辑仍在设置窗口中进行。

引擎摘要：

- 引擎名称
- 线程数
- Hash 大小
- 固定时间、固定深度或固定节点
- MultiPV

连线摘要：

- 前台/后台连线
- 识别扫描间隔
- 识别线程数
- 动画确认

“引擎设置”和“连线设置”必须放在对应摘要旁，不隐藏在通用设置菜单中。

### 3.4 设置窗口

所有弹窗统一使用标题说明、分组内容、行内验证、底部操作区和一致焦点顺序。

- 引擎管理：表格、添加、编辑、删除、空状态。
- 添加/编辑引擎：路径、名称、协议和引擎选项列表。
- 引擎时间设置：固定时间、固定深度、固定节点、MultiPV、引擎/库招延迟。
- 连线设置：鼠标间隔、扫描间隔、识别线程、后台连线、动画确认。
- 开局库设置：云库、超时、库招策略和延迟。
- 本地库管理：添加、删除、排序和空状态。
- 主题设置：亮色/暗色预览与棋盘样式。
- 局面编辑：棋子编辑、FEN、导入导出和确认操作。

## 4. 内部状态与组件边界

新增内部 `MainWindowState`，使用 JavaFX Property 作为 UI 投影层。现有业务逻辑仍由根控制器编排，设置提交后先更新现有 `Properties`，再刷新状态投影。

新增内部枚举：

```java
enum ConnectionUiState { DISCONNECTED, SELECTING_TARGET, CONNECTED, ERROR }
enum ConnectionMode { AUTO_PLAY, OBSERVE }
enum EngineUiState { UNLOADED, IDLE, THINKING, ERROR }
```

FXML 组件边界：

- 主窗口壳层
- 顶部导航和快捷操作
- 连线控制与状态摘要
- 引擎分析面板
- 棋谱/局势/开局库面板
- 统一设置弹窗壳层

根控制器保留现有 `EngineCallBack`、`LinkerCallBack`、`ChessManualCallBack` 入口；子控制器只负责绑定状态、渲染和触发命令。

## 5. 主题与视觉规范

- 使用语义色令牌，不在组件中散落硬编码颜色。
- 亮色：暖米白内容面、浅木棋盘、玉绿色激活态、朱红红方、深玉墨黑方。
- 暗色：墨色背景、低亮度表面、保持同一套玉绿/朱红语义色。
- 间距采用 4/8/12/16px 级别。
- 圆角使用 4/8/12px 层级，避免所有组件使用同一大圆角。
- 阴影只用于浮层、卡片和状态强调，不使用重阴影。
- 图标按钮必须同时有 Tooltip、可访问名称和可见状态文字；不能只用红绿颜色表达状态。

## 6. 实施顺序

1. 建立状态矩阵和本规格文件，冻结现有命令映射。
2. 增加 JUnit Jupiter 5.10.2 和 Surefire 3.2.5，先测试状态模型和摘要格式化。
3. 建立公共 CSS 令牌、控件状态、对话框壳层和 SVG 图标工厂。
4. 引入 `MainWindowState` 及三个状态枚举，接入现有连线和引擎回调。
5. 拆分主 FXML，先完成顶部导航与连线控制，再完成棋盘/分析双栏和右侧工作标签。
6. 按“引擎与连线 → 时间与开局库 → 主题与局面编辑”分组统一八个弹窗。
7. 清理不再使用的旧工具栏样式和节点级 stylesheet，保留业务仍使用的图像资源。
8. 完成编译、状态回归、窗口尺寸、高 DPI、主题和键盘操作验证。

## 7. 测试与验收

### 自动检查

```powershell
rtk mvn -q -DskipTests compile
rtk mvn -q test
```

测试状态模型、连线四状态、自动走棋/观战模式、引擎状态、设置摘要和非法输入提示。

### 启动与手工检查

```powershell
rtk powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

检查以下环境：1280×720、1366×768、1920×1080；Windows 缩放 100%、125%、150%；亮色和暗色主题。

验收条件：

- 九个 FXML 窗口均可加载，无字段注入或事件绑定异常。
- 所有现有命令仍可到达，设置持久化行为不变。
- 连线状态、连线模式和引擎状态不会混淆。
- 关键引擎和连线设置无需打开弹窗即可查看。
- 设置窗口可通过键盘操作，Enter/Space 激活，Esc 关闭。
- 无引擎、无棋谱、无库招、无候选着法等空状态有明确提示。
- 分析刷新保持现有约 100ms 节流，无明显布局抖动。

## 8. 边界与假设

- 不实现 Android 界面。
- 不更换引擎协议、连线识别算法、棋盘绘制算法或配置文件格式。
- 不自绘 Windows 标题栏。
- 不新增第三方 UI 控件库。
- 若现有资源与新 SVG 图标冲突，以新组件视觉为准，但不删除仍被业务使用的资源。
